## 3. RQ-123 发布后验证清单（首次实测结果）

```bash
cd backend && DATABASE_URL=postgresql://papertrade:papertrade@localhost:5433/papertrade \
  node src/scripts/verifyRelease.js
```

```
[ OK ] bundle-name: 线上与本地一致：/assets/index-D107n8oC.js
[ OK ] migration:   生产最新迁移 0019_v9_growth
[ OK ] routes:      7 个路由状态码均符合预期
[ OK ] telemetry:   埋点可写并已落库，探针记录已清理
[ OK ] errors:      发布后错误表新增 0 条
[ OK ] error-logs:  发布后日志新增 ERROR 0 条
结论：本次发布已验证。
```

设计取舍（三条不能退让的点）：

1. **埋点必须验证落库，不能只看状态码**。返回 200 但没写进库的埋点，比没有埋点更危险——它让所有指标看起来正常。
   脚本写一条带 `release-verify-probe` 标记的探针，确认入库后立即删除。
2. **需登录的端点以 401 为通过判据**。401 证明路由已挂载，404 才是没发上去。
   已下线路由则以 **410** 为通过判据（404 会被监控系统当成故障）。
3. **错误判定宁可多报不可漏报**。日志行无法解析为 JSON 时保守计入 ERROR，而不是跳过。

## 4. 本次修掉的两个真实缺陷（都是「写完没跑过真实链路」的代价）

| # | 现象 | 根因 | 修复 |
|---|---|---|---|
| 1 | **游客一开局就 500**（`blind_sessions_user_id_fkey` 外键 23503） | `identityOf()` 用 `Number.isFinite(Number(v))` 判用户 ID，而 `Number(null) === 0` → 游客被算成 **userId = 0** 写库 | `guestService.safeUserId()`：缺失归一为 `null`；`dailyChallengeService` 两处同类写法一并替换 |
| 2 | **游客额度形同虚设**（连开 10 局也不触发 429） | `created_at >= (now() AT TIME ZONE 'Asia/Shanghai')::date`：左侧是 timestamptz、右侧转 date 后按 **UTC 午夜**对齐，与上海日界错开 | 统一为 `GUEST_TODAY_SQL` 常量，两侧都先换算到上海时区再取日期 |

> 这两个缺陷 v9 完全没暴露：RQ-108 当时只有纯函数单测，**永远走不到外键与 SQL 时区那一步**。
> 这是本期写集成测试的直接动因——RQ-108 的验收标准「免登录能练一次」在真实链路上一直是失败的。

## 5. 关键设计取舍

| 决策 | 选择 | 理由 |
|---|---|---|
| RQ-126 公榜降级 | 只有 `publicBoardEnabled === false` **显式**传入时才关闭榜单 | 不传 = 「没统计活跃用户」，不等于「活跃用户为 0」；混同二者会让 v9 既有调用方凭空失去数据（P5 用例锁定该行为） |
| 连打的对比对象 | 与**上周的自己**比，而不是与人比 | 竞品「30 天净胜局榜」仅 9 人上榜——空榜在冷启动期是负资产；自我对比在任何用户量下都成立 |
| RQ-125 滑点写法 | 如实写「不引入滑点模型，成交价即收盘价」 | 用户能自己核对才是信任来源；写「有滑点模型」是伪结论 |
| 费用口径来源 | 从 `fees.js` 取，不在说明书里复制常量 | 后端费率是唯一事实来源，复制一份必然漂移 |
| RQ-122 未配域名时的处置 | 给**免费泛解析过渡域名**（IP 编进域名），不阻塞等决策 | 冷启动阶段最贵的是等待；正式域名到位后替换 `PUBLIC_BASE_URL` 即可 |
| 缺失值展示 | null/空串显示「—」，与数值 0 严格区分 | 把「没记录到价格」显示成「以 0 元成交」，在结算场景是最严重的误导 |
