### F-01（P0）· RQ-175 用「0 份文档」判通过 —— 生产假绿

- **问题现象**：`GET /api/public/stage-zero` 与 `?docs=1` 均返回
  `{"rq":"RQ-175","ok":true,"status":"pass","detail":"0 份文档均已包含对外地址。"}`；
  `/api/public/docs/rewrite` 同时返回 `available:[]`。
- **根因分析**：
  1. backend 镜像只 COPY `backend/`，`/app/README.md`、`/app/frontend/nginx.conf`、`.env` **均不存在**（已实证 `ls` 报 No such file）；
  2. `routes/public.js:197-205` 默认 `docs: []`，`?docs=1` 时 `filter(text.length>0)` 后仍是 `[]`；
  3. `auditDocsPublicness` 用 `bad.length === 0` 判 `ok`，空集合 → `true`（空集合真值 / vacuous truth）；
  4. `auditStageZero` 直接 `verdict: docs.ok === true` → **没有扫到任何东西，却被读成"审过且全部合格"**。
  这正是同文件 `public.js:215-216` 注释自己警告过的模式（"扫了但什么都没扫到，比不扫更危险，因为它长得像没找到违规"），在 docs 分支复发。
- **涉及文件与代码位置**：
  - `backend/src/services/stageZeroService.js` → `auditDocsPublicness()`（约 451 行）、`auditStageZero()` RQ-175 项与汇总 `note`（约 834 / 879 行）
  - `backend/src/routes/public.js:196-205`（`docsInput` 构造，本次**未改**，仅定位）
- **具体修改措施**：
  1. `auditStageZero` RQ-175 增加 `docs.total === 0` 守卫 → `verdict: null`（三态 `unknown`），`detail` 明确写出"生产镜像内无 README.md / frontend/nginx.conf，无法判定，不计为通过"；
  2. `auditDocsPublicness` 在 0 份文档时把 `note` 改为诚实文案；**保留 `ok:true` 既有契约**（单测 `v15StageZero.test.js:348` 已锁定其语义为"未发现违规"），避免破坏旧调用方；
  3. 汇总 `note` 在存在 `unknown` 时不再宣称「五项 P0 全部通过」。
- **验证结果**：生产 `RQ-175` 由 `pass` → `unknown / ok:false`，`unknown:['RQ-175']`，`docs.note` 与 `detail` 均如实说明；新增 8 条单测锁定，合法 2 份文档路径仍判 `pass`（零变化）。

### F-03（P1）· 生产停摆 4h12m 无自愈、无日志

- **问题现象**：11-03 20:48:55 优雅关闭后至 11-04 01:00 无任何应用日志；`docker` 报 daemon 不存在。
- **根因分析**：11-03 已把三容器 `restart` 改为 `always`，但那只能覆盖 **daemon 存活时** 的容器；Docker Desktop 进程本身未自启，整条链从最底层断了。**停摆期间应用没在跑，因此日志里没有任何"服务不可用"记录** —— 这是可观测性盲区。
- **涉及文件与代码位置**：`docker-compose.yml`（11-03 已修，本轮实证有效）；新增宿主层脚本。
- **具体修改措施**：新增 `backend/scripts/ensure-stack.ps1`：
  1. 健康 200 → 直接退出（零副作用）；
  2. 否则检查 daemon，未运行则拉起 Docker Desktop 并轮询就绪；
  3. 执行 `docker-compose up -d`，**刻意不带 `--build`**（避免把工作区在途代码推上生产）；
  4. 轮询 health 并把结果追加到 `backend/logs/stack-watch.log`。
  脚本**不自动注册计划任务**（改 OS 状态需运维确认），启用方式见第六节。
- **验证结果**：健康路径实测输出 `2026-11-04 01:16:43 OK health=200 (no action)`，日志正常落盘，三容器保持 healthy 未被改动。
- **附带实证**：本轮启动 Docker Desktop 后，mm8888 三容器**自动** `Up (healthy)`，证明 11-03 的 `restart: always` 修复在真实 daemon 恢复场景下生效（补齐了上轮 M-04 未做的端到端复验）。
