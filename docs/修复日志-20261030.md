## 2. 缺陷清单（4 项，均已修复）

> 四个缺陷**同属一个缺陷类**：入参只判「是不是数字 / 是不是整数」，**不判「是否在 PostgreSQL 能接受的范围内」**，

> 上一轮（10-29）已修 `parseIdParam` / `replay.compare` / `challenge.join` 三处，

### F-01（P0）日 K 线接口 `startSeq`/`endSeq` 越界 → 500

| 项 | 内容 |
|---|---|
| **问题现象** | `GET /api/stocks/600519/daily?startSeq=1&endSeq=1e20` → **HTTP 500**（`{"error":"服务器内部错误"}`），后端落一条 ERROR |
| **根因分析** | `routes/market.js:42`（修复前）用 `Number.isInteger(s) && Number.isInteger(e)` 判定是否启用区间分支。<br>`Number.isInteger()` 只判断「数学上是整数」**不做范围约束**，`1e20` 是数学整数 → 判定通过 → 原样下发 `WHERE seq BETWEEN $2 AND $3`。<br>`stock_daily.seq` 是 int4，PostgreSQL 抛 **22003 `value "100000000000000000000" is out of range for type integer`** → 兜成 500。<br>**触发必要条件**：`startSeq` 与 `endSeq` **必须同时提供**才会走进区间分支，只给一个时 `Number(undefined)=NaN` 自然被挡 —— 这也是单参数模糊测试**扫不到**它的原因。 |
| **涉及文件与位置** | `backend/src/routes/market.js:40-48`（区间判定）；新增 import 于 `market.js:6` |
| **修改措施** | 改用既有工具 `isDbInt()`（`utils/num.js:53`，同时约束 int4 上界 2147483647）。<br>判定失败时 `useRange=false`，回落「取最近 N 根」分支 —— **与 `abc`/`NaN` 等非法取值既有的降级口径完全一致**，不改变任何合法请求的结果。 |
| **验证结果** | 修复前 500 → 修复后 **200**。<br>合法性回归：`?startSeq=8600&endSeq=8610` 仍精确返回 **11 根（seq 8600~8610）**，区间分支未被误降级；不带参数仍返回默认 120 根（seq 8543~8662）。 |

### F-02（P0）双盲训练开局的 `startSeq`/`endSeq` 越界 → 500

| 项 | 内容 |
|---|---|
| **问题现象** | `POST /api/blind/start` body `{"code":"600519","startSeq":1e20,"endSeq":1e20,"bars":30}` → **HTTP 500** |

| **修改措施** | 改用 `isDbInt(Number(...))`。判定失败时回落 `pickRandomSegment()` 随机片段 —— 与该分支对 `abc`/`NaN` 既有的降级行为一致。 |
| **验证结果** | 修复前 500 → 修复后 **200**，返回 `{"id":11,...,"status":"RUNNING","segmentTag":"volatile"}`，DB 侧确认 `start_seq/end_seq` 回落为随机片段（8584~8613 / 920045）。测试会话已清理。 |

### F-03（P0）回放历史列表 `limit` 未取整 → 500

| 项 | 内容 |
|---|---|

### F-04（P0）净值对 benchmark 的 `days` 无上界 → 500

| 项 | 内容 |
|---|---|
| **问题现象** | `GET /api/review/benchmark?days=1e309`（或 `Infinity` / `2147483648` / `9223372036854775808`）→ **HTTP 500**，<br>对应两种 PG 报错：**22007** `invalid input syntax for type interval` 与 **22015** `interval field value out of range` |
| **根因分析** | `services/reviewService.js` `equityVsBenchmark()` 原实现 `const d = Number(days) >= 0 ? Number(days) : 30;`：<br>只排除了 NaN 与负数，**没有上界**。`Infinity`→`Number.isFinite` 之外被放过；`2147483648` 是有限正数也被放过。<br>两者都会拼进 `($n \|\| ' days')::interval` 触发 interval 解析/越界错误 → 兜成 500。 |
| **涉及文件与位置** | `backend/src/services/reviewService.js:385-389`（新增纯函数）+ `:574`（调用点）+ `:368`（常量） |
| **修改措施** | 新增并导出纯函数 `normalizeBenchmarkDays(raw, fallback = 30)`，语义**严格保持原样**：<br>`0` 是「全区间」哨兵值 → 原样保留；其余有限正数 → 收敛到 `[1, 3650]`；NaN/Infinity/负数/非法串 → 回落 30。<br>抽成纯函数是为了让这条边界能被**单测锁住**（内联在服务里则无法单测），与项目「把边界收敛到无 DB 依赖的纯函数再单测」的既有做法（见 `utils/num.js`）一致。 |
| **验证结果** | 修复前 500 → 修复后**全部 200**：`1e309`→30、`2147483648`→3650、`Infinity`→30、`9223372036854775808`→3650。<br>合法性回归：`0`→**0**（哨兵未被误改）、`7`→7、`30`→30、`90`→90、`400`→400、`abc`→30、`-1`→30，与原实现逐值一致。 |
