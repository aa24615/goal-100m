## 二、RQ-226 新增实现说明

### 2.1 文件清单

| 文件 | 作用 |
|---|---|
| `backend/src/services/diagnosisObjectionService.js`（新建，约 260 行） | 纯函数内核：诊断项抽取、异议校验、留痕构建、去重、归属隔离、汇总对账 |
| `backend/src/routes/diagnosis.js`（新建） | 3 个端点：`GET /api/diagnosis/catalog`、`POST /api/diagnosis/objections`、`GET /api/diagnosis/objections` |
| `backend/migrations/0022_v38_diagnosis_objection.sql`（新建） | `diagnosis_objections` 表 + 唯一去重索引 + 归属 CHECK 约束 |
| `backend/src/index.js`（改 2 行） | import + `app.use('/api', diagnosisRoutes)` |

### 2.2 关键设计决策

1. **不删除原诊断**：`applyObjections` 只在诊断项上叠加 `objected:true` + 理由 + 时间，原 `text` 保留——「你可以不同意我」≠「我把说过的抹掉」。
2. **归属双轨、绝不串号**：`ownerKeyOf` 把注册用户归一为 `u:<id>`、游客为 `g:<token>`；`null` userId 归 `null`（不落库），规避 v10 的 `Number(null)=0` 撞外键坑。迁移用 CHECK 约束保证 `user_id`/`guest_token` 有且仅有一列非空。
3. **去重**：同一 owner + session + diagnosis 只留一条，后写覆盖理由（与迁移唯一索引 `NULLS NOT DISTINCT` 对齐）。
4. **证据快照**：留痕时存 `evidence_text` + `sample_size`，日后可核对「当时给了什么结论」。
5. **只收结论类诊断**：`DIAGNOSIS_CATALOG` 只含 verdict/worstHabit/expectancy/discipline/tier 五个 inference 项；成本/行为是事实（RQ-225 可自行重算），不进「不同意」清单。

### 2.3 实现中发现并修复的真实 bug

- `normalizeDiagnosisKey` 原实现先 `.toLowerCase()` 再查 `CATALOG_KEYS`，导致驼峰 key `worstHabit` → `worsthabit` 恒匹配失败，所有驼峰诊断项无法标记。已改为「建小写索引映射回规范 key」。该 bug 由 RQ-226 P1 测试抓出。
