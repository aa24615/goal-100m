## 一、本轮结论（先说结果）

1. **运行期零 ERROR**：现存 15 份日志（覆盖 2026-11-13~11-28）聚合 `ERROR=0`；自 2026-11-03 起连续第 26 天无运行期 ERROR。WARN 三类（DB 冷启动重试 / token 到期 401 / WS 鉴权失败）经逐条溯源均为预期或已自愈，**无缺陷**。
2. **主动挖掘无 5xx**：6444 用例模糊（广域 5316 + 真实资源 1128）0 个 5xx；三层一致性（仓库/DB/镜像）全等。
3. **本轮唯一修复（配置漂移，P2）**：`backend/shot.mjs` 探测基址写死 `http://localhost:8080`，而 8080 自 11-08 起被无关 python 服务占用，README 截图脚本会截错页面。已抽纯函数从 `.env` 的 `WEB_PORT` 解析（与 compose/verifyRelease 同口径），并加 6 例单测锁定。
4. **服务恢复**：本轮开始时 Docker daemon 第 6 次停摆（入口 HTTP=000，日志断档于 11-28 00:06），用项目自带 `ensure-stack.ps1` 自愈成功（01:02:07 health=200）。但**计划任务仍未注册**，脚本依赖人工/自动化触发。

## 三、本轮修复项

### F-01（P2）：README 截图脚本 `shot.mjs` 探测基址写死 8080（配置漂移）

| 项目 | 内容 |
|---|---|
| **问题现象** | `backend/shot.mjs:19` `const BASE = 'http://localhost:8080'`。本机 8080 自 2026-11-08 起被无关 python（`url2pic`）占用，且本项目入口改为 `.env` 的 `WEB_PORT=8866`。运行 `node shot.mjs` 会导航到错误服务，截出无关页面或空白，README 截图失真。 |
| **根因分析** | 配置漂移（方法论 #31）：部署配置（`.env` WEB_PORT / compose `${WEB_PORT:-8080}`）在 11-08 变更，工具脚本内写死的默认值未同步。此类缺陷不产生 5xx、不写 ERROR、模糊测试也扫不到，只能靠周期性核对「脚本端口 vs compose/.env」发现。与上轮已修的 `ensure-stack.ps1`（11-22）、`verifyRelease.js`（11-26）属同一缺陷类。 |
| **涉及文件与位置** | `backend/shot.mjs:19`（原写死 BASE）、`backend/scripts/shotBase.js`（新增纯函数）、`backend/tests/unit/shotBase.test.js`（新增单测） |
| **修改措施** | ① 抽纯函数 `resolveShotBase({ envText, explicit })`：显式 `SHOT_BASE_URL` 优先 → 从 `.env` 的 `WEB_PORT` 解析 → 无配置/非法回退 8080，口径与 `verifyRelease.js:resolveVerifyPort` 完全一致；② `shot.mjs` 用 `fileURLToPath(import.meta.url)` 定位仓库根 `.env`（与 cwd 无关），替换写死 BASE；③ `main()` 打印 `探测基址 BASE=...` 防再次静默漂移；④ 新增 6 例单测锁定三种口径。 |
| **兼容性** | 显式环境变量优先，合法请求/行为零变化；仅当无 `.env` 且无环境变量时才回退 8080（与原行为一致）。脚本不在容器镜像内（`backend/Dockerfile` 只 COPY src/migrations/node_modules），业务运行路径零影响。 |
| **验证结果** | 新单测 6/6；全量 `npm test` **1460/1460**（基线 1454 + 新增 6）；`node --check shot.mjs` 语法 OK；纯函数实测从 `.env` 解析出 `http://localhost:8866`。已 commit `95c20ae`，双推 GitHub + CNB，按规则完成本机 build + 重部署。 |

## 六、本轮方法论沉淀

- **第 34 条**：配置漂移横扫要覆盖「一次性工具脚本」（截图、诊断、发布校验），它们不在运行路径、不进镜像，日志与模糊均扫不到，但会在被调用时静默产出错误结果。修一处（ensure-stack/verifyRelease）必须沿同类扫全库（shot.mjs 即本轮扫出）。
- **第 35 条**：daemon 停摆已第 6 次复现，且 `stack-watch.log` 末条持续不前进 = 守护脚本未注册的**客观证据**。今后每轮开头先看该日志末条时间戳，落后即强调计划任务缺口（P1），不要仅满足于「本次自愈成功」。
