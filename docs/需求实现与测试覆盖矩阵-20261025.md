## 0. 优先级定义（P0 ~ P5）

v6 需求表只标到 P2。为让「正常流程 / 边界 / 异常 / 合规」四类场景都有可归属的层级，
本矩阵向下延伸 P3 ~ P5，形成六级刻度。**P0~P2 是需求优先级，P3~P5 是用例性质**：

| 级别 | 含义 | 判定标准 | 失败后果 |
|---|---|---|---|
| **P0** | 需求优先级 P0：核心闭环、资金与数据安全、合规口径 | 需求表标注 P0 的**正常流程** | 阻断发布 |
| **P1** | 需求优先级 P1：体验与留存增强 | 需求表标注 P1 的正常流程 | 阻断本迭代验收 |
| **P2** | 需求优先级 P2：可延后增强 | 需求表标注 P2 | 记入技术债 |
| **P3** | **边界条件**：任意需求的空值 / 0 / 负数 / NaN / 非法 ID / 门槛临界值 | 输入处于合法域边缘 | 产生错误结果或崩溃 |
| **P4** | **异常与降级**：网络失败、服务不可用、并发重入、数据源中断、脏数据 | 依赖方失效 | 静默错误或 500 |
| **P5** | **合规与口径一致性**：免责声明、样本门槛文案、常量唯一来源、埋点脱敏、训练隔离 | 文案/常量与实现漂移 | 合规风险、不可观测 |

> 每个用例在用例名里直接带 `Pn` 前缀（如 `P3 · RQ-77 49 笔仍不达标`），
> 便于 `node --test` / `vitest run` 输出里直接读出覆盖层级。
