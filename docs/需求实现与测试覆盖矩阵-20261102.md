## 4. 本期修掉的真实缺陷（测试发现的，不是需求写的）

1. **`reconcileConsistency` 把 `null` sessionId 算成 0**（`Number(null)===0` 有限数）
   → 「未携带 sessionId」被静默归类为「session 0」，漏报永远查不出来。与 v10 的 `identityOf` 是同一族缺陷，已加显式守卫。
2. **扫描窗口固定 600 字符会跨到下一条查询**：短文件里「一条声明了口径」会把紧随其后的未声明查询一起判通过——
   这正是 v12 `analyticsService` 漏掉的方式。改为**取到语句结束**（反引号/分号）再兜底 600。
3. **`checkPublicOwner` 的 README 正则漏了管道符两侧的空格**：README 已经写了责任人，检查却报「未写明」。
4. **`checkPublicOwner` 只读 `backend/.env`**：本项目 `.env` 在仓库根，该项此前永远读到空文件。已两处都读并回显扫描过的路径。
5. **容器里看不到责任人**：compose 不会透传未声明的键，`.env` 写了 owner 容器仍读不到 → 已在 `docker-compose.yml` 显式声明三个变量。
6. **生产埋点对账实际不一致**：上线首跑即抓出 `event#4528(session=324)`、`event#4538(session=7)` 两条孤立 `blind_finish`。
   → 补上「会话级打标传播」规则，并把 user 3（占全部埋点 83%）标为自测账号后，对账归零。
