## 3. 修复清单

### F-01 WebSocket 重连风暴加固 【高】

- **修改文件**：`frontend/src/ws.ts`
- **修改措施**：
  1. 固定 2000ms 重连 → **指数退避**（`1000 × 2^n`，上限 30s）
  2. 叠加 **±30% 抖动**，避免多标签页同时重连形成尖峰
  3. 增加**次数上限 10 次**，超限挂起不再冲击服务端
  4. **后台标签页暂停重连**，`visibilitychange` 恢复可见时重置退避并补连（历史风暴正是"挂着过夜的页面"所致）
  5. 连接成功即重置退避计数；`reconnect()` 主动重连也重置

```ts
const RECONNECT_BASE_MS = 1000;
const RECONNECT_MAX_MS = 30_000;
const RECONNECT_MAX_ATTEMPTS = 10;

function nextReconnectDelay(): number {
  const exp = Math.min(RECONNECT_MAX_MS, RECONNECT_BASE_MS * 2 ** reconnectAttempts);
  const jitter = 0.7 + Math.random() * 0.6; // ±30%
  return Math.round(exp * jitter);
}
```

- **验证结果**：22/22 前端测试通过；`tsc --noEmit` 零错误；带有效 token 连接仍正常（收到 `snapshot` 28 只标的）

### F-02 WebSocket 客户端 IP 解析 【中】

- **修改文件**：`frontend/nginx.conf:22-33`、`backend/src/middleware.js:26-64`、`backend/src/index.js:21,114-160`
- **修改措施**：
  1. **nginx**：`/ws` 块显式补 `X-Real-IP` / `X-Forwarded-For`（nginx 子块不继承上层 `proxy_set_header`）
  2. **后端**：新增导出函数 `proxyClientIp(req, hops)`，按**与 Express/proxy-addr 完全等价**的算法回推真实 IP：`index = min(len - 1, TRUST_PROXY_HOPS)`
  3. 常量 `TRUST_PROXY_HOPS = 1` 与 `app.set('trust proxy', 1)` 对齐，保证 HTTP / WebSocket **两条链路安全语义一致**，都不会被伪造前缀欺骗

```js
export function proxyClientIp(req, hops = TRUST_PROXY_HOPS) {
  const raw = req?.headers?.['x-forwarded-for'];
  if (typeof raw === 'string' && raw.trim()) {
    const list = raw.split(',').map((s) => s.trim()).filter(Boolean);
    if (list.length > 0) return list[Math.min(list.length - 1, hops)];
  }
  return req?.socket?.remoteAddress || 'unknown';
}
```

- **算法依据**（实测 `proxy-addr@2` + `express/lib/utils.js:223`）：Express 的 `trust proxy = N` 编译为 `(a, i) => i < N`，`proxyaddr()` 返回截断数组的**末位**，等价于取 `min(len-1, N)`；已用 `XFF: 1.2.3.4, 192.168.96.1` 与 `a, b, c` 两组样例验证一致
- **验证结果**：
  - 修复前 `{"ip":"::ffff:192.168.96.4"}` → 修复后 **`{"ip":"192.168.96.1"}`**（真实客户端，与 HTTP 日志一致）
  - 容器内 nginx 已确认生效；新增 6 条单元测试覆盖伪造前缀 / 单跳 / 超跳 / 无 XFF / 空值 / 缺 socket
