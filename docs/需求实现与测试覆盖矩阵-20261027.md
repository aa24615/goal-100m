## 1. 优先级模型说明

需求文档只定义了 **P0 / P1 / P2** 三级（产品优先级）。测试要覆盖正常流程、边界与异常，因此沿用 v7 起已验证有效的做法，**扩展为六级测试优先级**：

| 级别 | 含义 | 本文件覆盖内容 |
|---|---|---|
| **P0** | 核心主流程 | 需求验收标准逐条对应的「能不能用」断言 |
| **P1** | 差异化功能 | 需求文档里被点名为「差异化 / 创新」的能力 |
| **P2** | 留存体验 | 引导、空态、可关闭提示这类体验项 |
| **P3** | 边界与异常 | null / 脏入参 / 越界 / 接口失败 / 除零 |
| **P4** | 性能与并发 | 大样本聚合与高频调用的耗时预算 |
| **P5** | 兼容与回归 | 旧字段语义不倒退、常量结构稳定、合规硬约束 |

> 关键取舍：**P3/P4/P5 是测试自创的级别，不是产品优先级**。产品说 P1 的需求，测试仍然会写它的 P3 边界用例——否则「脏数据打崩页面」这类问题永远不会在发布前暴露。

## 6. 本次踩坑（可复用）

1. **「不得包含 X」的断言要排除否定句**。站内提示的免责声明里写着「不承诺任何奖励」，成绩卡的「不给出胜率类结论」同理——直接扫全文必然失败。改为只扫 `title + body`。
2. **`await findByTestId(x).textContent` 拿不到内容**。`await` 优先级高于取属性，实际求值的是 `Promise.textContent`。必须写成 `(await screen.findByTestId(x)).textContent`。
3. **需求变更会推翻既有测试的前提**。RQ-95 让 12 笔样本的比率指标不再渲染，直接打挂了 3 条旧断言。正确做法不是放宽断言，而是**把 fixture 改成按 `sampleSize` 推导 `ratioGate`**，让「指标渲染类」用例显式声明自己的样本量。
4. **jsdom 没有 `document.execCommand`**，剪贴板降级分支要自己造桩才能测到。
5. **新增服务要避免循环 import**：`northStarService` 依赖 `analyticsService` 的留存口径，但 `analyticsService` 不能反向依赖它；`auth.js` 引入 `track` + `normalizeChannel` 前先确认 `analyticsService` 不依赖 `auth`。
6. **Express 路由顺序**：`/blind/resume` 必须注册在 `/blind/:id` 之前，否则会被当成 `id=resume` 走 400 分支——这正是 F-25 说的「噪声来源」之一。
