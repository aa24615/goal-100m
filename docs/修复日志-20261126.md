## 二、本轮修复项

### 修复 1（P1）：守护脚本 `ensure-stack.ps1` 健康探测端口写死 8080

| 维度 | 内容 |
|---|---|
| **问题现象** | 脚本 `-HealthUrl` 默认值写死 `http://localhost:8080/api/health`。而 11-08 起本机入口已改为 `.env` 的 `WEB_PORT=8866`（8080 被无关 python 服务占用）。健康时误判失败、宕机时探测错误入口并可能误报 exit 5。该修复 11-22 已做但滞留工作区 4 天未入库。 |
| **根因分析** | 配置漂移：端口变更提交（11-08 `5564595`）后，未同步核对守护脚本的默认值。属方法论 #31「脚本默认值 vs 部署配置」类缺陷，不产生 5xx、日志与模糊均扫不到。 |
| **涉及文件与位置** | `backend/scripts/ensure-stack.ps1:27`（param 默认值）、`:70-83`（新增端口解析块）、`:86`（新增 `Write-Log "INFO healthUrl=..."`） |
| **修改措施** | 默认值改为空串 → 按 `ComposeDir/.env` 的 `WEB_PORT` 解析，无 `.env` 回退 8080（与 compose `${WEB_PORT:-8080}` 同口径）；显式传参仍优先；新增日志行防止再次静默漂移。11-23 真实停摆场景已验证自愈有效。 |
| **提交** | `d6350c9`，已双推 GitHub + CNB |

### 修复 2（P1）：发布校验脚本 `verifyRelease.js` 默认端口写死 8080

| 维度 | 内容 |
|---|---|
| **问题现象** | 不传 `--base` 时 `defaultBaseUrl()` 默认 `http://localhost:8080`。本机 8080 是无关服务，导致 `telemetry`、`stage-zero`、`status-truth` 三项 `fetch failed`，`verifyRelease` 误报 5 个 FAIL；本轮实测传 `--base=http://localhost:8866` 后仅 1 个 FAIL（产品项）。 |
| **根因分析** | 与修复 1 **同一缺陷类**（端口配置漂移）——上一轮横扫时漏掉了此脚本。属方法论 #16/#31：修完一处要沿同类横向排查。 |
| **涉及文件与位置** | `backend/src/scripts/verifyRelease.js:23-28`（用法注释）、`:68-85`（`defaultBaseUrl()` 改为解析 `.env`）、新增导出纯函数 `resolveVerifyPort()`；新增 `backend/tests/unit/verifyReleasePort.test.js`（5 例） |
| **修改措施** | 抽纯函数 `resolveVerifyPort(envText)`：从 `.env` 的 `WEB_PORT` 解析端口，非法/缺失回退 8080，跳过注释行；`defaultBaseUrl()` 显式环境变量（`VERIFY_BASE_URL`/`PUBLIC_BASE_URL`）仍优先，否则读仓库根 `.env`，无则回退 8080。该脚本为独立 CLI，不在服务启动路径，无需重建容器。 |
| **提交** | `b0affa4`，已双推 GitHub + CNB |
